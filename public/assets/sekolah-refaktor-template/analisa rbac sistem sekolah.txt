Berikut adalah **hasil generasi Role Based Access Control (RBAC) berdasarkan Scope** dari informasi yang Anda berikan. Saya menyusunnya agar **siap digunakan sebagai blueprint sistem RBAC untuk Sistem Manajemen Sekolah**, termasuk **deskripsi tugas operasional dan hak akses sistem** dari setiap role.

Struktur ini juga mempertimbangkan:

* **Multi-Role User**
* **Scope akses berbasis unit / kelas / individu**
* **Role transisional (PPDB → Siswa)**
* **Pemisahan jabatan struktural dan fungsional**

---

# 1. Konsep Scope dalam RBAC Sistem Sekolah

Dalam sistem sekolah, **scope menentukan batas akses role terhadap data tertentu**.

| Jenis Scope    | Contoh          | Penjelasan                                           |
| -------------- | --------------- | ---------------------------------------------------- |
| Global Scope   | Seluruh sekolah | Digunakan oleh role manajemen seperti Kepala Sekolah |
| Unit Scope     | Modul tertentu  | Contoh: keuangan, perpustakaan                       |
| Class Scope    | Kelas tertentu  | Guru dan wali kelas                                  |
| Subject Scope  | Mata pelajaran  | Guru mapel                                           |
| Student Scope  | Siswa tertentu  | Orang tua                                            |
| Personal Scope | Data pribadi    | Siswa                                                |
| Process Scope  | Tahapan sistem  | PPDB                                                 |

---

# 2. Role Berdasarkan Scope Sistem Sekolah

## 2.1 Role Transisional (PPDB / Admissions)

### 1. Calon Siswa (Applicant / Prospect)

**Scope:**
Formulir pendaftaran miliknya sendiri.

**Tugas Operasional**

* Mengisi formulir pendaftaran
* Mengunggah dokumen persyaratan
* Melihat status seleksi
* Melakukan daftar ulang jika diterima

**Hak Akses Sistem**

| Modul              | Akses           |
| ------------------ | --------------- |
| PPDB Form          | Create / Update |
| Dokumen            | Upload          |
| Status Seleksi     | Read            |
| Profil Pendaftaran | Update          |

---

### 2. Panitia PPDB

**Scope:**
Semua data pendaftar PPDB.

**Tugas Operasional**

* Memverifikasi dokumen pendaftar
* Mengelola kuota penerimaan
* Menginput hasil seleksi
* Mengelola tahapan PPDB

**Hak Akses Sistem**

| Modul              | Akses           |
| ------------------ | --------------- |
| Data Pendaftar     | Read            |
| Verifikasi Dokumen | Update          |
| Hasil Seleksi      | Create / Update |
| Kuota PPDB         | Update          |

# 9. Contoh Multi-Role User

Contoh user:

**Ibu Maya**

Memiliki 3 role:

1️⃣ Wakasek Kurikulum
2️⃣ Guru Kimia
3️⃣ Orang Tua Murid

Sistem akan menggunakan **Role Context Switching**.

User memilih mode:

```
Login
↓
Pilih Role
```

Dashboard berubah sesuai role.

Contoh:

Mode Guru
→ Input nilai kimia

Mode Wakasek
→ Kelola jadwal sekolah

Mode Orang Tua
→ Lihat nilai anak
